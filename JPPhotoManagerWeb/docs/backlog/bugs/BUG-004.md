# BUG-004 — Sync/Convert directory pairs are saved and used with no containment check

- **Steps to reproduce:** (inferred from code reading; not yet reproduced at runtime)
  1. Authenticate as a normal user.
  2. `PUT /api/sync/configuration` (and `PUT /api/convert/configuration`) with a source or destination directory outside `photomanager.root-catalog-folders`, such as `/etc` or `/`.
  3. An administrator runs the sync with "delete files missing from the source".
- **Expected:** configured directories are canonicalized (`toRealPath()`) and rejected unless they sit inside the configured roots.
- **Actual:** `SaveSyncConfigUseCaseImpl` stores any path, and `StorageServiceAdapter` does no canonicalisation or containment check in any method, so a sync can copy to, or delete from, arbitrary server paths.
- **Environment:** both — a validation defect, independent of the deployment.
- **Schema change:** no
- **Notes:** `infrastructure/service/StorageServiceAdapter.java`, `application/usecase/sync/SaveSyncConfigUseCaseImpl.java`, `SyncController.setConfiguration`, `ConvertController.setConfiguration`. Verify which of the configuration and run endpoints are restricted to `ADMIN`; no `@PreAuthorize` shows on `SyncController`. Suggested fix: one `resolveWithinRoots()` in the adapter. Same cause as BUG-005. Source: security review 2026-10-15, §2.1/§7.
