# BUG-007 — `assets.hash` has no index

- **Steps to reproduce:**
  1. Catalog a large library.
  2. Open the duplicates view or the home statistics, or upload a file.
- **Expected:** hash lookups and duplicate grouping use an index.
- **Actual:** `findByHashNotDeleted` (`WHERE a.hash = :hash AND a.deletedAt IS NULL`), `findDuplicateHashes` (`GROUP BY a.hash`) and `countDuplicates` (a correlated subquery grouped by hash) all scan `assets` sequentially; V32 made `hash` nullable and the async pipeline writes it later via `updateHash`.
- **Environment:** both — grows with library size.
- **Schema change:** yes — a new Flyway migration, for example `CREATE INDEX ix_assets_hash ON assets(hash) WHERE hash IS NOT NULL`, optionally `CONCURRENTLY` outside a transaction.
- **Notes:** `infrastructure/persistence/jpa/JpaAssetRepository.java`; no migration under `db/migration/` creates an index on `hash`. Source: database review 2026-10-15, §3.2.
